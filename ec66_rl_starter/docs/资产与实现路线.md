# EC66：URDF、USD 与强化学习实现路线

## 已作出的技术选择

EC66 第一版强化学习任务采用：

```text
EC66 simplified URDF -> Newton ModelBuilder.add_urdf() -> 并行 Newton 环境
                                                     -> RSL-RL PPO
```

**第一版不要求 USD，也不安装完整 Isaac Sim。**

现有 `C:\newton\ec66_sand\assets\ec66_simplified.urdf` 已被当前独立 Newton 场景使用；Newton 可以直接导入它。Cartpole 已经证明 RSL-RL、Torch、GPU、Newton 的训练/回放/导出链路可用。

## URDF 与 USD 的准确边界

Isaac Lab 的 `Articulation` 资产最终工作在 USD/UsdPhysics 场景图上；`UrdfFileCfg` 虽然让用户直接填写 URDF，但内部会先执行 URDF→USD 转换再 spawn。因此，“Isaac Lab 拒绝 URDF”不准确，更准确的说法是：**标准 Isaac Lab 资产路线以 USD 为运行时表示，URDF 是可自动转换的输入格式。**

当前安装采用 kit-less Newton 路线，没有完整 Isaac Sim 的 URDF importer 扩展。Gate 2 因此选择 Newton 的 `ModelBuilder.add_urdf()` 原生入口，直接载入 URDF；这条路径不要求手工生成 USD。

这不表示 URDF 文件坏了，也不表示将来永远不能转 USD。若以后需要 Isaac Sim 的 RTX 相机、GUI 导入工作流或 PhysX 资产管线，可以另外安装完整 Isaac Sim 并执行转换；那是一个独立的大型环境选择，不是 Reach-v0 的前置条件。

## 两条路线的取舍

| 路线 | 资产入口 | 现在可用 | 第一版是否推荐 | 适用场景 |
| --- | --- | --- | --- | --- |
| Newton 原生 | URDF 直接由 `ModelBuilder.add_urdf()` 导入 | 是 | **是** | 无沙 Reach-v0、RSL-RL、批量并行训练 |
| Isaac Lab / Isaac Sim 工作流 | `UrdfFileCfg` 自动转换或预先转成 USD，再使用标准场景/资产类 | 当前 kit-less 环境不可用 | 否 | RTX 视觉、复杂 USD 场景编辑、PhysX 对比 |

## 当前版本与资产边界

| 项目 | 当前状态 | 对 Gate 2 的决定 |
| --- | --- | --- |
| RL 环境 | Python 3.12、Isaac Lab 3.0.0-beta2、Newton 1.2.1 | 所有 Reach 代码只使用这套环境已验证的 API |
| 原沙土环境 | 系统 Python 3.13、Newton 1.6.0 | 与 RL 环境隔离，不直接复制 `newton.controllers` 代码 |
| simplified URDF | 由基本几何体组成，当前 Newton 场景可加载 | Gate 2 使用它验证控制和学习闭环 |
| 用户提供 URDF / STL（2026-09-19） | `C:\newton\assets` 内 14 处引用可解析，7 个机器人 mesh 非空；独立 flan.STL 为空、URDF 法兰盒尺寸为零 | 代理模型先跑通锅体接触；真实铲子的单位、挂载和凹形碰撞需核对，见甄锅均料任务文档 |

Newton 1.2.1 的 Isaac Lab 适配层没有可直接使用的重力补偿接口，且该环境中没有系统 Newton 1.6.0 的 `newton.controllers` 模块。Reach-v0 不需要绕过这个限制：第一版使用关节位置目标加 PD/joint drive。若以后确实需要模型补偿控制，应在 Reach-v0 之后评估整体版本升级或自行基于动力学量实现，不能混用两套 Python 环境。

## Reach-v0 的实际架构

```text
ec66_sand/assets/ec66_simplified.urdf
                  |
                  v
src/ec66_rl/newton_native/scene_builder.py
  读取 URDF；创建 N 份固定基座 EC66；定义 TCP 与关节限位
                  |
                  v
src/ec66_rl/newton_native/reach_env.py
  reset / step / observation / reward / done
                  |
                  v
src/ec66_rl/rsl_rl_adapter.py
  把批量 Torch 张量暴露给 RSL-RL PPO
                  |
                  v
logs -> checkpoint (.pt) -> 回放 -> ONNX 导出
```

`reach_contract.py` 已经定义了与物理引擎无关的 22 维 observation、6 维 action 和 reward。`reach_env.py` 的职责是用 Newton 的真实状态填充这些量；它不重新定义奖励。

## 实施顺序

### A. 单环境 smoke test ✅ 已完成

在 RL 虚拟环境中直接用 `ModelBuilder.add_urdf()` 导入 EC66，创建固定基座与地面；只执行 reset 和零动作步进。

验收结果：URDF 可导入、6 个关节顺序与限位正确、TCP 可计算；250 个控制步无 NaN、越界或发散，PD drive 能保持姿态并响应小目标变化。

### B. 单环境 Reach-v0 ✅ 固定目标已完成

加入一个可见目标球。动作是 6 个关节目标的小增量，交给关节位置 PD/joint drive。先固定一个目标点。

验收结果：固定目标、22 维 observation、reward/success/reset 已验证，铲斗前缘 TCP 可进入 3 cm 目标球。

### C. 可达目标随机化 ✅ 已完成局部范围

在收紧后的安全关节范围内采样目标姿态 `q_goal`，用 FK 生成 `goal_xyz`。先不要猜测一个笛卡尔长方体；`configs/reach_v0.yaml` 中的 `sampling_bounds_m` 保留为待测项，等 FK 样本覆盖范围稳定后再填写。

已验证局部目标的运动学可达性；有甄锅后的碰撞与工作空间覆盖需重新验收。

### D. 向量化

由一个“单环境 builder”复制出 N 个 world；所有 `q`、`qd`、TCP、goal、reward 都保持在 GPU 张量中。

验收：例如 64 个环境可同时 reset/step，彼此状态隔离。

### E. 接入 RSL-RL

实现最小向量环境适配器，输入 observation 批量张量，接收 `[N, 6]` action，并返回 reward/done。

验收：PPO 的 reward 和 episode length 比随机策略高；回放后能到达随机目标。

### F. 只在 Reach-v0 成功后增加沙土

在 MPM 物料标定之前，先做独立 XPBD 粗颗粒铲面接触诊断（2026-09-20 已实现，见《颗粒铲面验收.md》）。它不是 MPM 的替代标定，不升级现有 Newton，也不改变旧 Reach 策略。下一步验证运动中承料与倾倒，再选择并验证物料求解器及耦合方案。加入料面观测和新奖励后需要明确新的 observation/action 契约并重新训练，不直接复用 Reach checkpoint 为抛洒策略。

## 不应做的事

- 不把 Cartpole 的 `policy.onnx` 接到 EC66；它的输入是 `[1, 4]`，输出是 `[1, 1]`，而 EC66 Reach-v0 是 22 维 observation 和 6 维 action。
- 不为了第一版 Reach-v0 先安装完整 Isaac Sim 或转 USD。
- 不修改已验证的 `ec66_sand` phase 1–3 文件；RL 新代码应完全位于 `ec66_rl_starter`。
- 不在 Gate 2 中引入 MPM、双向耦合或模型重力补偿；这些都不是 TCP reach 策略训练与执行的前置条件。
- 不把系统 Python 的 Newton 1.6.0 包或控制器文件复制进 Isaac Lab 的 Newton 1.2.1 环境；若升级，必须整体验证兼容版本组合。
