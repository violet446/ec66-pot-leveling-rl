## 0. 一句话总览

```text
EC66 的 URDF  ──►  Newton 物理世界（N 份并行）
                        │
                        │  ①读出 q / qd / TCP
                        ▼
                  22 维 observation  ──►  PPO 策略网络  ──►  6 维 action ∈ [-1,1]
                        ▲                                        │
                        │                                        │ ②q_target = clamp(q + a×0.04)
                        │                                        ▼
                        │                              MuJoCo 关节位置 PD drive
                        │                                        │
                        │                                        ▼
                        └────────── ③reward ◄──────── Newton 再走 4 个物理子步
```

- **训练**：上面这个环在 64 个并行世界里同时跑，PPO 用采到的经验更新网络。
- **执行**：训练完把网络冻结导出成 `policy.pt`，让它在这个环里只做"看状态→给动作"，不再更新参数。
- **两个完全不同的"导入模型"**：①导入**机械臂模型**（`scene_builder.py` 读 URDF）；②导入**训练好的策略模型**（`torch.jit.load` 读 `policy.pt`）。本文第 4 节和第 8 节分别讲。

## 4. 第一部分：模型导入（URDF → Newton）

### 4.1 URDF 里到底有什么

`C:\newton\ec66_sand\assets\ec66_simplified.urdf`（由 `ec66_sand` phase 1 生成，7 KB）：

- 结构：`base_link` → `joint1` → `link1` → … → `link6` → `flange_joint`(fixed) → `flange_link` → `scoop_mount`(fixed) → `scoop_link`
- 6 个 `revolute` 关节（`joint1..joint6`），每个都带 `limit lower/upper/effort/velocity` 和 `dynamics damping/friction`
- 惯量来自公开的 Elite Robots EC66 URDF；几何体是**简化代理**（球/圆柱/长方体），不是官方 STL 网格
- `scoop_link` 是铲斗：底板 `box size="0.43 0.36 0.012"` 在 `origin xyz="0.415 0 -0.025"`，所以板在 `scoop_link` 局部坐标里占 **x ∈ [0.20, 0.63]**，两侧各一块 `box size="0.43 0.012 0.10"` 当侧板，质量暂定 **1 kg**（未标定）
- 基座固定（`floating=False`），所以没有浮动基座的 6 个自由度

关节限位与速度上限（直接从 URDF 读出来）：

| 关节 | lower | upper | velocity (rad/s) | effort (N·m) |
| --- | ---: | ---: | ---: | ---: |
| joint1 | -6.2832 | 6.2832 | 2.6199 | 150 |
| joint2 | -6.2832 | 6.2832 | 2.6199 | 150 |
| joint3 | -2.7925 | 2.7925 | 3.3161 | 150 |
| joint4 | -6.2832 | 6.2832 | 4.5379 | 28 |
| joint5 | -6.2832 | 6.2832 | 4.5379 | 28 |
| joint6 | -6.2832 | 6.2832 | 4.5379 | 28 |

注意 joint1/joint2 的"限位"实际是 ±2π（≈无限位），joint3 才有真实的 ±2.7925。这一点在 Gate 2F 做工作空间分层时会很重要。

### 4.2 导入代码逐行拆解

全部导入逻辑在 `scene_builder.py` 的 `_build_ec66_template()`：

```35:71:src/ec66_rl/newton_native/scene_builder.py
def _build_ec66_template(*, kp: float, kd: float) -> newton.ModelBuilder:
    if not EC66_URDF.is_file():
        raise FileNotFoundError(f"EC66 URDF not found: {EC66_URDF}")
    if kp <= 0.0 or kd < 0.0:
        raise ValueError(f"Invalid drive gains: kp={kp}, kd={kd}")

    builder = newton.ModelBuilder(up_axis=newton.Axis.Z)
    newton.solvers.SolverMuJoCo.register_custom_attributes(builder)
    builder.add_urdf(
        str(EC66_URDF),
        xform=wp.transform_identity(),
        floating=False,
        enable_self_collisions=False,
        collapse_fixed_joints=True,
        ignore_inertial_definitions=False,
        force_position_velocity_actuation=True,
    )
```

每个参数为什么这样写：

| 代码 | 含义 / 为什么 |
| --- | --- |
| `up_axis=newton.Axis.Z` | 声明世界 Z 轴朝上，URDF 的关节轴向解释依赖它 |
| `SolverMuJoCo.register_custom_attributes(builder)` | **必须在 `add_urdf` 之前**。MuJoCo 求解器需要向 builder 注册它自己的附加属性（`joint_target_ke/kd/mode` 等）；漏掉这步后面设增益会在 finalize 报错 |
| `xform=wp.transform_identity()` | 基座就在世界原点。注意 `ec66_sand` 用的是 `BASE_POSITION=(-1.48,-0.122,0.95)`（为了配合料箱），RL 工程刻意挪回原点，减少无关变量 |
| `floating=False` | 固定基座 → 关节坐标数 == 自由度数 == 6，obs 里的 q/qd 各 6 维才成立 |
| `enable_self_collisions=False` | Reah-v0 不需要自碰撞；也在 Gate 2A/2B 阶段省掉大量接触开销 |
| `collapse_fixed_joints=True` | 把 fixed 关节折叠掉。`flange_joint` 和 `scoop_mount` 都是 fixed，折叠后**只剩 link1..link6 六个刚体**，铲斗的质量与几何被合并进 link6 |
| `ignore_inertial_definitions=False` | 使用 URDF 里的惯量（不用几何体反推），保持与 EC66 公开参数一致 |
| `force_position_velocity_actuation=True` | 强制使用位置/速度执行器语义，这样后面设 `joint_target_pos` + `ke/kd` 就能形成 PD 行为 |

紧接着是**三道自检**，任何一道不过就直接抛异常，避免"模型长得不对还继续训练"：

```53:61:src/ec66_rl/newton_native/scene_builder.py
    if builder.joint_dof_count != 6 or builder.joint_coord_count != 6:
        raise RuntimeError(
            f"Expected 6 EC66 coordinates/DOFs, got coordinates={builder.joint_coord_count}, "
            f"DOFs={builder.joint_dof_count}"
        )
    if tuple(builder.joint_label) != JOINT_NAMES:
        raise RuntimeError(f"Unexpected joint order: {builder.joint_label}")
    if tuple(builder.body_label) != BODY_NAMES:
        raise RuntimeError(f"Unexpected body order: {builder.body_label}")
```

其中标签常量带上 URDF 的机器人名做前缀：

```21:22:src/ec66_rl/newton_native/scene_builder.py
JOINT_NAMES = tuple(f"ec66_simplified/joint{index}" for index in range(1, 7))
BODY_NAMES = tuple(f"ec66_simplified/link{index}" for index in range(1, 7))
```

> 这三道自检是"关节顺序"的唯一保险。**顺序错了训练一定失败**，而且表现得很像"奖励设计有问题"，非常难查。所以宁可让它编译期就炸。

然后写初始状态和关节驱动：

```63:69:src/ec66_rl/newton_native/scene_builder.py
    builder.joint_q[:] = INITIAL_JOINT_POS.tolist()
    builder.joint_target_pos[:] = INITIAL_JOINT_POS.tolist()
    builder.joint_velocity_limit[:] = URDF_VELOCITY_LIMITS.tolist()
    for dof in range(6):
        builder.joint_target_ke[dof] = float(kp)
        builder.joint_target_kd[dof] = float(kd)
        builder.joint_target_mode[dof] = int(newton.JointTargetMode.POSITION)
```

- `INITIAL_JOINT_POS`（单位 rad，来自 `ec66_sand` 已验证的无碰撞参考姿态）：
  `[-0.001132283, -0.979132976, 2.058742307, -4.221201981, 1.571928620, 1.570796329]`
- `URDF_VELOCITY_LIMITS = [2.6199, 2.6199, 3.3161, 4.5379, 4.5379, 4.5379]`（= URDF 的 velocity 字段）
- `DEFAULT_KP = 1200.0`，`DEFAULT_KD = 80.0` —— 与 `ec66_sand` phase 1 相同的增益，是**仿真参数，不是辨识出来的真实 EC66 伺服增益**
- `JointTargetMode.POSITION`：把 `joint_target_pos` 解释成位置目标，PD 由 `ke/kd` 提供

> 这里有个容易误解的点：**策略输出的不是力矩**，是有限的关节目标位置增量；力矩由 MuJoCo 的 PD（ke/kd）内部算出来，并受 URDF 的 `effort` 上限约束。

### 4.3 单环境 vs N 个并行环境

```74:96:src/ec66_rl/newton_native/scene_builder.py
def build_ec66_model(
    device: str = "cuda:0",
    *,
    kp: float = DEFAULT_KP,
    kd: float = DEFAULT_KD,
    num_envs: int = 1,
) -> newton.Model:
    """Load and finalize one or more independent fixed-base EC66 worlds."""
    if num_envs < 1:
        raise ValueError("num_envs must be at least one")
    template = _build_ec66_template(kp=kp, kd=kd)
    if num_envs == 1:
        builder = template
    else:
        builder = newton.ModelBuilder(up_axis=newton.Axis.Z)
        builder.replicate(template, world_count=num_envs)

    model = builder.finalize(device=device)
    lower = model.joint_limit_lower.numpy()[:6]
    upper = model.joint_limit_upper.numpy()[:6]
    if np.any(INITIAL_JOINT_POS < lower) or np.any(INITIAL_JOINT_POS > upper):
        raise RuntimeError("The Gate 2A initial pose violates an EC66 joint limit")
    return model
```

- **URDF 只解析一次**（`_build_ec66_template`），然后用 `builder.replicate(template, world_count=N)` 复制成 N 个独立世界。这比解析 N 次 URDF 快得多，也是 64 环境的实现基础。
- `finalize(device=device)` 之后，所有数组都在 GPU 上（`cuda:0`）。
- 最后再核对一次初始姿态在限位内。

### 4.4 TCP 是怎么定义的（重要）

Reach-v0 的"末端"不是法兰，而是**铲斗前缘的中点**：

```17:20:src/ec66_rl/newton_native/reach_env.py
# The selected TCP is the center of the scoop's cutting edge.  The scoop plate
# spans x=[0.20, 0.63] m in scoop_link coordinates and is centered at z=-0.025
# m.  Applying flange_joint and scoop_mount gives this link6-local offset.
TCP_OFFSET_LINK6 = np.array([-0.025, -0.719, -0.00047661], dtype=np.float32)
```

因为两个 fixed 关节都被折叠了，铲斗已经"长在" link6 上，所以 TCP 用**link6 位姿 + 固定偏移**算出来：先取 `body_q[link6]` 的位置和四元数，再把偏移量按四元数旋转后相加：

```79:86:src/ec66_rl/newton_native/reach_env.py
    def _tcp_from_state(self, state: newton.State) -> np.ndarray:
        link6_pose = state.body_q.numpy()[self.link6_index]
        position = link6_pose[:3]
        quaternion = link6_pose[3:7]
        return (position + _rotate_xyzw(quaternion, TCP_OFFSET_LINK6)).astype(np.float32)

    def tcp_position(self) -> np.ndarray:
        return self._tcp_from_state(self.state_0)
```

### 5.1 Observation（22 维，固定顺序）

- `ACTION_SCALE_RAD = 0.04`：**每个控制周期允许策略改变的最大关节目标 = 0.04 rad（≈2.3°）**。20 Hz 下理论最大关节速度 0.8 rad/s，远低于 URDF 的 2.6–4.5 rad/s，这是安全边界。

### 5.3 Reward（每控制步）


PPO 路径的实现（`rsl_rl_env.py:127-132`）：

```127:132:src/ec66_rl/newton_native/rsl_rl_env.py
        progress = self.previous_distance - distance
        rewards = 2.0 * progress - 0.2 * distance - 0.01 * torch.mean(bounded.square(), dim=-1)
        successes = distance <= 0.03
        rewards = rewards + 10.0 * successes.float()
```

- `progress` 项：每接近一点点就有正反馈。否则策略要偶然进入 3 cm 球才第一次拿到分，早期几乎没有梯度信号。
- `distance` 项：没有进步时仍然偏好靠近目标。
- `action²` 项：偏好平稳控制。
- `+10` / `-5`：把"成功"和"失败"变得毫无歧义。
- 终止条件：`successes | time_outs`。**成功立即结束回合并重置**，超时也重置。
- `time_outs` 会作为 `extras["time_outs"]` 传给 RSL-RL，PPO 用它做超时自举（避免把"时间到了"误当成"任务失败"）：


### 5.5 Reset 与目标采样

`reset(env_ids)` 是"重开一局"，做四件事（`rsl_rl_env.py:158-180`）：

1. **决定本回合的起始姿态**：`random_starts=True` 时用 `_sample_initial_joint_positions()` 在标称姿态附近随机扰动（上界 `SAFE_START_DELTA_RAD`），否则用标称姿态
2. `physics.reset(env_ids, joint_positions=start)`：把 `q` 置为该姿态、`qd=0`、清力、重新 `eval_fk`，并把 PD 目标也设为该姿态。**注意 `batched_env.reset()` 在 Gate 2F 之后新增了可选的 `joint_positions` 参数**（`batched_env.py:86-112`）
3. 采样目标（见下）
4. 复位记账量：`previous_action=0`、`episode_length_buf=0`、`episode_return=0`、`previous_distance=‖goal-tcp‖`

随机目标的生成方式**不是**在笛卡尔长方体里乱采样，而是"采样关节姿态 + FK 求 TCP"：

```117:144:src/ec66_rl/newton_native/rsl_rl_env.py
    def _sample_reachable_goals(self, env_ids: torch.Tensor) -> None:
        """Sample safe joint poses and use FK to produce guaranteed-reachable goals."""
        self._assign_goal_distance_bounds(env_ids)
        pending = env_ids
        delta_limit = SAFE_GOAL_DELTA_RAD.to(self.device)
        initial_tcp = self.physics.tcp_position
        max_sampling_attempts = 256
        for _ in range(max_sampling_attempts):
            if pending.numel() == 0:
                break
            random_delta = (
                2.0 * torch.rand((pending.numel(), 6), generator=self.rng, device=self.device) - 1.0
            ) * delta_limit
            candidates = (self.physics.joint_position[pending] + random_delta).clamp(
                self.physics.joint_lower[pending], self.physics.joint_upper[pending]
            )
            trial_q = self.goal_joint_pos.clone()
            trial_q[pending] = candidates
            trial_tcp = self.physics.tcp_for_joint_positions(trial_q)
            distances = torch.linalg.vector_norm(trial_tcp[pending] - initial_tcp[pending], dim=-1)
            accepted = (distances >= self.goal_distance_min[pending]) & (
                distances <= self.goal_distance_max[pending]
            )
            accepted_ids = pending[accepted]
            if accepted_ids.numel() > 0:
                self.goal_joint_pos[accepted_ids] = candidates[accepted]
                self.goal_position[accepted_ids] = trial_tcp[accepted_ids]
            pending = pending[~accepted]
```

Gate 2F 之后的关键行为变化：

- **采样基准是"本回合的当前关节姿态"**（`self.physics.joint_position[pending]`），**不再是固定的 `initial_joint_pos`**。这是随机起点能与随机目标组合起来的前提
- `SAFE_GOAL_DELTA_RAD = [0.30, 0.25, 0.25, 0.20, 0.20, 0.20]`：相对本回合起点允许的关节偏移上限
- **距离分层**（`GOAL_DISTANCE_BANDS_M`）：`near` 0.10–0.20 / `medium` 0.20–0.32 / `far` 0.32–0.45 m。`goal_distance_band=None`（训练默认）时每个环境随机抽一个层，从而**均衡覆盖三层**；指定 `--distance-band near|medium|far` 时全部用同一层，供分层评估使用
- **最多拒绝采样 256 轮**，超了抛 `RuntimeError` 并列出未满足的区间（`rsl_rl_env.py:145-156`）
- 目标由 FK 生成 → 一定可达

这就是 README 里"Gate 2F 已通过"的含义：目标始终是"**距本回合起点** 0.10–0.45 m 的局部目标"，只是起点和距离层都随机化了。它仍然**不是**全工作空间能力。

### 7.4 PPO 超参与网络结构（`make_train_cfg`）

环境/运行层：

| 键 | 值 | 含义 |
| --- | --- | --- |
| `seed` | 42 | 训练用的全局种子 |
| `num_steps_per_env` | 24 | 每次迭代每个环境采 24 步（= 1.2 s 仿真，250 步回合的约 1/10） |
| `max_iterations` | 命令行 | 300 |
| `save_interval` | `max(10, iterations//5)` | 300 → **每 60 次迭代存一次** |
| `logger` | `tensorboard` | 事件文件写在 `log_dir/events.out.tfevents.*` |
| `resume` | `False` | 不续训 |
| `check_for_nan` | `True` | 每步检查 obs/reward/done，NaN 立刻报错 |
| `clip_actions` | 1.0 | 送进环境前把动作裁到 [-1,1] |
| `obs_groups` | actor/critic 都用 `["policy"]` | 22 维 |

网络：

| 键 | 值 |
| --- | --- |
| `actor.class_name` | `MLPModel` |
| `actor.hidden_dims` | `[64, 64]` |
| `actor.activation` | `elu` |
| `actor.obs_normalization` | `False` |
| `actor.distribution_cfg` | `GaussianDistribution`, `init_std=0.8`, `std_type="scalar"` |
| `critic` | 同结构，`distribution_cfg=None`（输出单个 value） |

PPO 算法：

| 键 | 值 | 说明 |
| --- | --- | --- |
| `num_learning_epochs` | 5 | 每批数据复用 5 遍 |
| `num_mini_batches` | 4 | 1536 → 4×384 |
| `learning_rate` | 1e-3 | `schedule="adaptive"`，按 KL 自动缩放 |
| `desired_kl` | 0.01 | 自适应学习率的目标 KL |

| `entropy_coef` | 0.005 | 探索强度（对应动作标准差） |
| `clip_param` | 0.2 | PPO 的比率裁剪 |
| `max_grad_norm` | 1.0 | 梯度裁剪 |
| `value_loss_coef` / `use_clipped_value_loss` | 1.0 / True | critic 损失 |
| `normalize_advantage_per_mini_batch` | False | |
| `rnd_cfg` / `symmetry_cfg` | None | 不用 RND / 对称增强 |

> 配置里那个 `"empirical_normalization": {}` 在 **RSL-RL 5.0.1 里没有任何代码读取**（整包检索无匹配），是沿用旧模板留下的空字段。真正决定要不要归一化的是 actor/critic 的 `obs_normalization`。因为 observation 已经手工设计成接近 [-1,1]（q 归一化、qd 除 2.0、tcp_to_goal 单位 m、distance 标量），这里保持 `False` 是有意的。

> `num_steps_per_env=24` 的选择逻辑：回合长 250 步，24 步 ≈ 1/10 回合。太小会让 GAE 的 0.99^24 ≈ 0.79 折扣几乎没起作用；太大（比如 250）则每次迭代都要等一整个回合，早期探索慢。

### 7.5 训练内部时序（一次迭代）

```
it 循环体：
  ① 采样 24 步（torch.inference_mode）：
       actions = PPO.act(obs)        # 高斯采样，带探索噪声
       obs, rewards, dones, extras = env.step(actions)
       check_for_nan(obs, rewards, dones)
       PPO.process_env_step(...)     # 超时自举 → 存入 RolloutStorage
       logger.process_env_step(...)  # 累积 episode return / length
  ② PPO.compute_returns(obs)        # 反向算 GAE / returns
  ③ 5 epochs × 4 mini-batches：actor-CVaR 损失 + value 损失 + 熵 → Adam
  ④ logger.log(...)：写 TensorBoard（含 learning_rate、action_std）
  ⑤ it % 60 == 0 → save(model_it.pt)
```

`env.step()` 里对 `done` 的环境**立即 reset 并重新采样目标**（`auto_reset=True`），所以 64 个环境的回合是各跑各的、异步交错，不需要等所有环境同时结束。

### 8.1 三个产物的用途区分

| 文件 | 里面是什么 | 什么时候用 |
| --- | --- | --- |

| `exported/policy.onnx` | 同一张图的 ONNX | 脱离 PyTorch 的部署（C++/TensorRT/工控机） |

导出时 actor 被包装成"只看张量、只出张量"的模块：

```210:214:env_isaaclab/Lib/site-packages/rsl_rl/models/mlp_model.py
    def forward(self, x: torch.Tensor) -> torch.Tensor:
        """Run deterministic inference on pre-concatenated observations."""
        x = self.obs_normalizer(x)
        out = self.mlp(x)
        return self.deterministic_output(out)
```

两个关键结论：

1. **输入是拼接好的原始张量，不是 TensorDict**。所以回放/评估里必须传 `env._observations_tensor()`，不能传 `env.get_observations()`：

```71:73:src/ec66_rl/newton_native/play_random_policy.py
            with torch.inference_mode():
                action = self.policy(self.env._observations_tensor())
                _, _, dones, extras = self.env.step(action, auto_reset=False)
```

2. **导出的是确定性输出（分布均值）**。`GaussianDistribution(std_type="scalar")` 的 `deterministic_output()` 就是"原样返回"，`as_deterministic_output_module()` 是恒等映射：

```182:188:env_isaaclab/Lib/site-packages/rsl_rl/modules/distribution.py
    def deterministic_output(self, mlp_output: torch.Tensor) -> torch.Tensor:
        """Extract the mean from the MLP output."""
        return mlp_output

    def as_deterministic_output_module(self) -> nn.Module:
        """Return an export-friendly module that extracts the mean from the MLP output."""
        return _IdentityDeterministicOutput()
```

所以**部署时的动作是可复现的**：同一个 observation 一定得到同一个 action（训练时的随机性来自 `std_param`，导出时被丢掉了）。这对真机安全很关键。

> 顺带说明：`obs_normalization=False` 时 `obs_normalizer` 是 `nn.Identity()`，导出模块里带着的是这个恒等层。如果将来把 `obs_normalization` 改成 `True`，导出的模块会 `deepcopy` 一份冻结的归一化统计量，**外部调用方式不变**（仍然只喂 22 维原始观测）。

```text
│   control.joint_target_pos = q_target
│   ke = 1200, kd = 80, mode = POSITION
│         src/ec66_rl/newton_native/scene_builder.py:66-69

```

**执行阶段不需要的东西**（也是训练阶段才有的）：

- `reward`、`dones`、`extras` —— 真机上"成功"仍然要算（用来判断该换下一个目标），但 reward 只是日志，不参与任何更新
- `RolloutStorage`、optimizer、critic —— 全都不需要，导出时已经丢掉
- `_sample_reachable_goals()` —— 真机上目标由上层任务系统给（比如"去料箱 A 上方 20 cm"），不是随机采样

**执行阶段必需但当前只在仿真里有的东西**：

- `batched_env.reset()` 把 `q` 硬置为 `INITIAL_JOINT_POS`：真机上只能"移动到这个姿态"，必须检查路径无碰撞、速度受限
- `joint_lower/upper` 直接来自 URDF：真机上要用**实测标定后的**软限位，并留安全余量
- `disable_contacts=True`：真机上碰撞不会被仿真拦住，必须由独立的安全层（外部的力矩/电流监控、工作空间盒、急停）负责

### 8.5 从"仿真跑通"到"真机跑通"还差什么

按 `docs/roadmap.md`，这是 Gate 6 的内容。当前项目**没有任何真机通信代码**（全工程检索 `modbus` / `sdk` / `serial` / `socket` 零命中），所以需要新建：

| 缺什么 | 说明 |
| --- | --- |
| 通信层 | EC66 的 SDK / Modbus TCP / EtherCAT 客户端，负责下发关节位置指令、读回关节角与速度 |
| 安全层（**必须在策略之外**） | 关节软限位、速度限幅、力矩/电流限幅、工作空间盒、碰撞检测、急停按钮 |
| 状态对齐 | 真机的关节零位、单位（EC66 部分控制器用 degree）、关节顺序必须与 URDF 完全一致 |
| 时序 | 真机控制周期要与训练时的 0.05 s 对齐；指令下发抖动会直接改变 observation 分布 |
| 观测一致性 | `q_normalized` 用的 `joint_lower/upper` 也要用真机同一套；`previous_action` 必须保存上一步真正下发的 a |
| 分级放行 | 顺序是：离线回放 → 限速空载 → 限速带载 → 正常速度 |

**最重要的一条**：`policy.pt` 只是一个 22→6 的函数，它**没有安全能力**。限位、速度、力矩、急停都必须在它外面用独立的代码实现，不能指望奖励让策略学会安全。

## 10. 已知边界与坑

### 10.1 能力边界（现在**不**代表什么）

- 100% 成功率只覆盖**距本回合起点 0.10–0.45 m 的局部区域**。Gate 2F 已经把起点和距离层都随机化了，但 `SAFE_GOAL_DELTA_RAD` 仍把目标限制在起点附近，起点本身也只在 `SAFE_START_DELTA_RAD` 的范围内随机。不能读成"全工作空间能力"。
- 无沙、无料箱、无接触、无视觉。物理里 `disable_contacts=True`。
- 256 个并行环境没跑过（只跑过 1 / 16 / 64）。
- 不需要 USD / 完整 Isaac Sim；URDF 由 Newton 原生 `add_urdf()` 直接读。

### 10.2 具体坑清单

| # | 坑 | 现象 | 处理 |
| --- | --- | --- | --- |
| 1 | 中文用户名 | `invalid PCH directory` / `CUDA kernel build failed with error code 6` | 设 `TEMP/TMP/WARP_CACHE_PATH` 到 ASCII 目录（`runtime_env.py` 也做了兜底，但要在 import newton 前） |

## 11. 下一步（Gate 3）：要改哪几个文件

Gate 2F 已完成（随机起点 + 三层均衡目标；三层冻结评估各 100/100）。当前主线是 Gate 3（`docs/roadmap.md:108-112`）：**加入一个简单刚体障碍物/标记物，验证接触检测与碰撞惩罚，同时保留无接触 Reach 回归测试**。验收：策略达到目标且不触碰禁止区域。

按当前代码结构，改动会集中在这几处：

| 文件 | 要改什么 |
| --- | --- |
| `scene_builder.py` | 现在只搭机械臂。要新增料箱 / 障碍标记物的几何与碰撞形状（可参考 `ec66_sand/ec66_scene.py` 的 `add_bin()` 用多段 box 拼环形，而不是薄三角网格） |
| `batched_env.py` | 求解器目前硬写 `disable_contacts=True, use_mujoco_contacts=False`，`njmax/nconmax` 也只是保守值。Gate 3 必须改这三处，并把**接触力/接触点读出来** |
| `reach_contract.py` | 契约里的 `failure_penalty` / `safety_failure` 通道**已经预留好但从未被触发**（见 5.3），Gate 3 正好把它接上。新增观测量只能追加到 22 维末尾，并把维度改大 |
| `rsl_rl_env.py` | `_observations_tensor()` 拼接新观测；`step()` 里算碰撞惩罚。**遵守 `docs/task_contract.md:15` 的约定：新增内容只能追加到末尾，否则 2F 的策略直接失效** |
| `docs/roadmap.md` + `README.md` | 记录 Gate 3 验收数字，并保留 Reach-v0 的回归入口 |
| `configs/reach_v0.yaml` | 5.4 的技术债仍未还。Gate 3 要改奖励系数时会更容易误导人，**建议先修** |

**推荐的最小验证顺序**（延续现在的习惯：先证明物理/任务没问题，再谈学习）：

1. 加了料箱后，仿照 `gate2f_test.py` 写一个检查：用 oracle 诊断控制器跑足够多回合，确认**不撞箱也能到达目标**（证明任务本身可解）；
2. 再单独验证碰撞检测：故意让 oracle 撞上去，确认能读出接触并触发惩罚；
3. 短跑 `--num-envs 16 --iterations 20` 探活，看 `/success_rate` 与碰撞计数有没有信号；
4. 才考虑正式训练，并**同时跑一次 Reach-v0 回归**确认没退化。
